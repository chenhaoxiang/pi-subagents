# Community 0.76.1 maintained upgrade

## Scope and source

Owner authorized updating the maintained version and the local installation, retaining fork fixes. The target is **0.76.1-fork.1**, with an immutable GitHub tag/Release and compiled installable package.

- Previous integration main: `b0cd036c8ea690f04e58fb57419e68dfac03e3df` (0.76.0-fork.2).
- Community main: `7d072b91dca7e1aa915282f0159cec0175d65efa` (manifest 0.76.1). At preflight, the community Latest GitHub Release still said v0.76.0; branch version and stable Release status are separate evidence.
- Existing local installed repair: `5a69711e0d80a9e0a2dc2d80f4f3e5096023e076`, a clean three-file model-pool update, replayed with original commit provenance.
- Preserve refs: `preserve/main-before-0.76.1-20261006` and `preserve/installed-model-pool-before-0.76.1-20261006`. Old source/worktree and package remain available; they are not the new release installation source.

## Integrated community fixes

- Keep Pi’s base prompt first, followed by child boundary/structured-output instructions.
- Report the actual per-tool timeout cause rather than an unrelated run deadline.
- Doctor and launch admission count the same async capacity and spawn-budget scope.
- Stop a paused run even when its result was already delivered and its writer exited.
- Preserve completed result handling and display a restart-required error instead of mixing package versions after an in-place update.
- Do not mark the Herdr pane as needing human action merely because a child needs its parent agent.

## Preserved fork behavior

- Five-model heterogeneous pool: Kimi high, GPT-6.1-sol xhigh, GPT-6-astra high, GLM high, DeepSeek high. Opus is explicit-only; no per-model runtime/tool/budget caps are added.
- Fallback only before child tool activity; explicit chains, registry skips and actual attempts remain observable.
- Activity-based idle timeout, host/runner compatibility and fail-closed behavior remain.
- bg_wait defaults to 60 minutes; call-level timeout is blocking-only and short non-blocking subscription misuse remains rejected.

## Merge and verification

Text conflicts occur only in package version, lockfile version metadata and CHANGELOG. Runtime auto-merges must still be semantically checked: run/tool timeout precedence, child prompt ordering, stop/result writer ownership, and doctor session-scoped admission are validated together with fork fallback/idle/background-wait behavior. Do not discard fork controls or weaken tests merely to make the community merge green.

Run typecheck/build, targeted unit/integration regressions, tool-activation smoke and all required platform CI. Inspect and smoke-load the actual compiled tarball in an isolated agent directory without model prompts or real credentials. CI/publication/installation evidence is reported separately; an unrun complete local suite is not called green.

## Installation and rollback

Create the Release from exact regular-merged main; attach the compiled tarball, source manifest and SHA256SUMS. Download and verify the public assets before installing. Keep the existing local source/compiled package and prior configuration declaration as the rollback path. Install only one Subagents source in personal settings; preserve every unrelated package/setting.

No running parent or child is forcibly stopped/reloaded. **Restart Pi after the update**: 0.76.1 detects old imported modules and may intentionally reject /reload for an in-place version change. Disk installation and live-session activation are distinct.
